# Contributing

Thank you for helping improve the course. Issues and pull requests are
welcome for unclear specifications, incorrect tests, broken links, and
portability problems on x86-64 Linux distributions.

## Ground rules

- Keep each current assignment unfinished. Completed prerequisites are published
  reference modules and may be improved together with their tests. Changes to a
  prerequisite must be applied consistently to every snapshot that contains it.
- A change to a contract (a README rule, a public signature, or a test) must
  update all three together and explain why in the pull request.
- Course sources and handouts are English. `python3 scripts/check_language.py`
  enforces this boundary. Historical theory material under `examples/` is
  multilingual and is retained independently of the class snapshots.
- Keep fixtures small and generated by the system toolchain inside tests; do
  not commit binary objects.

## Checks

The handout must build and lint cleanly while its behavioral tests fail:

```sh
cargo fmt --all --check
cargo clippy --locked --workspace --all-targets -- -D warnings
cargo test --locked --workspace --no-run
python3 scripts/check_language.py
python3 scripts/audit_course.py --starter
cargo test --locked --workspace --test prerequisites
```

Maintainers additionally validate an independent reference implementation on
native Linux before a release: all tests in debug and release, every grader at
100/100, representative mutations rejected, and the unchanged starter failing
exactly at its task holes. `docs/validation/` records that evidence for each
class.

## Reporting a test or specification bug

Include the class, the test name, your distribution and toolchain versions
(`rustc -V`, `cc --version`, `as --version`), and the smallest input that
shows the problem. Please describe the behavior you expected from the
specification rather than sharing your implementation.

# Independent snapshot release validation

## Scope and environment

The release contains class0–class15 as independently buildable projects. Each
current assignment retains its task holes. Earlier modules are completed
reference implementations, identical across every snapshot that includes them.
No personal exercise implementations or local IDE files are part of the release.
Historical theory examples under `examples/` retain their published contents.

Validation ran on native x86-64 Linux with Rust/Cargo 1.93.1, Clippy 0.1.93,
and GNU Binutils 2.46. Executable tests use native system-toolchain fixtures.

| Completed reference, release | 1,235 passed; none failed |
| Local grader, class0–class15 | Every stage 100/100, with cumulative debug and release checks passing |
| Representative defect injection | Four reference mutations rejected; two release-audit mutations rejected |

Test counts include prerequisite contracts repeated in the independent snapshots;
they are not counts of distinct test designs. Completed current-task references
are maintained outside the student checkout and are not selected by a feature
flag or included as alternate implementations.

The reference mutations changed overflow error classification, accepted an
out-of-range signed LEB128 operand, removed the appended-file allocation limit,
and removed the combined debug-group budget. Each selected test passed on the
reference and failed after its corresponding mutation. Audit mutations removed a
task marker and diverged a copied prerequisite module; both were rejected.

## Reproducing the student release gates

On native x86-64 Linux, from the repository root:

```sh
cargo fmt --all --check
python3 scripts/check_language.py
python3 scripts/audit_course.py --starter
cargo clippy --locked --workspace --all-targets -- -D warnings
cargo test --locked --workspace --tests --no-run
cargo test --locked --workspace --test prerequisites
```

`cargo test --workspace --test contract --no-fail-fast` deliberately fails on the
initial release. Those tests become the student's acceptance checks. After
completing a snapshot, run `python3 scripts/grade.py classN` for that snapshot.
The grader does not depend on assignments in neighboring directories.

## Reviewed invariants

- Input byte ranges distinguish arithmetic overflow from file bounds before
  indexing. Integer readers retain full field widths and byte order.
- Symbol selection preserves input order, strong/COMMON/weak precedence, and
  exact symbol identities without cloning the selected map entry on each lookup.
- Relocation arithmetic uses explicit wrapping or checked operations according
  to the field contract; failure leaves the destination unchanged.
- Layout uses bounded offsets and fixed segment storage. Native startup assembly
  belongs to each complete snapshot and is built with the native toolchain.
- CIE signed LEB128 operands reject values outside the 64-bit representation.
- Debug collection bounds combined group bytes and padding before growth.
  Section attachment bounds the final file, including names and headers, before
  allocating alignment padding or appending data.
- Immutable prepared inputs carry validated relationships through PIE, TLS,
  unwind, debug, and ICF lowering. Compiler-facing integration tests exercise the
  cumulative backend rather than delegating linking to a system linker.
